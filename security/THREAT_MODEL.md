# Threat model

What PerfAgent protects, from whom, and how. Each principle is mapped to the code that implements it so a change cannot silently remove a protection without the matching test going red.

## Assets

| Asset                                                                  | Why it matters                                                     |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------ |
| The user's source code                                                 | Read by the scanner; snippets may be sent to the AI the user chose |
| Secrets in the project (`.env`, keys, tokens in code, cookies in HARs) | Must never be read, stored, displayed, exported or sent            |
| The user's AI API keys and bill                                        | Stored by PerfAgent; misuse costs money                            |
| The user's git repository and working tree                             | Fixes write files; nothing may be lost or pushed                   |
| The user's machine and network                                         | A local server is a classic target for browser-based attacks       |
| Reports in `.perfagent/`                                               | May contain URLs and request data from staging/production          |
| Trust in the tool                                                      | A tool that reads code must be boring and predictable              |

## Attackers

| Attacker                                                             | Capability                                                  | Goal                                                                                                |
| -------------------------------------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| A malicious web page open in the same browser                        | Can send requests to `127.0.0.1:4545` (CSRF, DNS rebinding) | Read reports or source, trigger scans, open files, apply fixes                                      |
| A malicious imported file (JSON, HAR, PDF, Excel, Word, pasted text) | Content fully attacker-controlled                           | XSS in the dashboard, huge allocation, prompt injection into the AI, path tricks in `location.file` |
| A scanned web page                                                   | Controls everything the browser loads                       | Prompt injection via page text, SSRF via redirects, resource exhaustion                             |
| A compromised or malicious AI response                               | Returns arbitrary text                                      | Make PerfAgent write outside the root, run commands, push, exfiltrate                               |
| Another user on the same network                                     | Can reach the machine's IP                                  | Reach the dashboard                                                                                 |
| A compromised dependency or publish pipeline                         | Code in the package                                         | Everything                                                                                          |
| An operator of a hosted/static instance                              | Has the server                                              | Use the scanner to reach internal systems (SSRF)                                                    |

Out of scope: an attacker already running code as the user on the user's machine; the security of the scanned sites and AI providers themselves.

## Residual risks

- **Local mode trusts the local user.** Anyone with the token and access to the loopback interface has the same powers as the user who started PerfAgent. The token is printed in the terminal and in the browser URL; a screen recording or shared terminal leaks it for the lifetime of that process. Restart to rotate.
- **Redaction is pattern-based.** Unusual secret formats can slip through. `ai.sendCode: 'none'` removes the risk for AI; exports should still be reviewed before sharing.
- **The AI can be wrong or manipulated.** A prompt injection in a scanned page can produce a misleading patch. Review before accept is the control; `fix.review: false` turns it off on purpose and still runs tests and re-tests.
- **Redirect-time SSRF.** `assertUrlAllowed` checks the URL before navigation; redirects inside the browser to private addresses are not re-checked today. Hosted instances must run the browser in an isolated network namespace.
- **Static website quick test** calls Google's PageSpeed Insights API from the visitor's browser; Google's quota and privacy terms apply.
- **Dependencies.** Playwright, zod, ws, ECharts, Three.js, React and the MCP SDK are large; Dependabot and CodeQL reduce but do not remove the risk.
- **Docker image.** The server binds to `127.0.0.1` inside the container; publishing the port with `-p` does not work on its own. `--network host` exposes it to the host only; a reverse proxy with authentication is required for anything else, and PerfAgent cannot enforce that.
