# Rules

Every problem PerfAgent reports comes from a rule in `packages/rules/src/packs/*.ts`. A rule has an id, a pack, a technical title, a plain-language sentence, a severity, the metrics and areas it touches, a `why`, fix steps, docs links and a `detect` function that looks at the project scan (static) and/or the page results (runtime). The engine (`packages/rules/src/engine.ts`) turns each finding into an `Issue` with a root cause chain, an estimated gain, before/after changes and a budget suggestion.

Packs: `general`, `realtime`, `ai` and `agents` are always on. `react` is added for React, Next.js and Remix projects; `next` for Next.js. Override with `rules.packs: [...]`; switch single rules off with `rules.disable: ['id']`.

Severity: critical, warning, info. Confidence under 0.6 is shown as "probable". "Auto" means the rule engine can apply the change itself, without AI.

## Adding a rule

1. Add a `Rule` object to the matching pack file in `packages/rules/src/packs/`, or a new pack file and one line in `allRules` in `packages/rules/src/index.ts`.
2. Give it an id `pack/kebab-name`, a `title`, a `plain` sentence, `why`, `steps`, `docs` and a `detect` that returns `Finding[]` using the helpers `loc`, `lineText`, `snippet`, `pageMetric`, `replaceLine`.
3. Add a fixture that triggers it (in `fixtures/demo-shop` or a small file under `packages/rules/test`) and a test.
4. Mention it in the matching guide under `docs/guides/` and in this file.
